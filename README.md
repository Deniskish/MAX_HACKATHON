# Опора — финансирование и поддержка бизнеса в MAX

Опора помогает предпринимателю описать бизнес и задачу, сравнить официальные инструменты поддержки и подготовить документы. GigaChat понимает свободный запрос и историю, предлагает заполнение, ищет материалы, объясняет сценарии, проверяет документы и готовит черновики. Условия и расчёты проверяются кодом. [Архитектура, настройка и границы AI](docs/ai-platform.md).

Аудитория: российские ООО/АО, ИП, фермерские хозяйства и команды, которым пока не принадлежит юридическое лицо. Приложение не подаёт заявки, не выдаёт кредиты и не обещает совместимость программ.

## Сценарий

Автоматический каталог Минфина, AI-проверка новых мер и уведомления в приложении и MAX: [настройка и ограничения](docs/live-funding.md).

1. Добавить бизнес по ИНН либо выбрать «У меня пока нет компании».
2. Для компании получить сведения через DaData (при настроенном серверном ключе) либо из импортированного индекса ФНС. Неизвестные поля можно дополнить вручную. Без подключённого источника API вернёт 503, без найденной записи — 404. Подстановки вымышленных компаний нет.
3. Указать цель, при желании сумму, срок, собственные средства и потребность в залоге.
4. Нажать «Найти варианты». Открыть карточку, проверить совпавшие, неизвестные и невыполненные условия и официальный источник.
5. Сохранить возможность или начать подготовку: описание проекта, список документов, чтение TXT/PDF/DOCX/сканов, AI-проверка и редактируемый черновик.
6. Отметить комплект после самостоятельной сверки с оператором. Итог: «Комплект готов к проверке перед подачей». Реальной отправки нет.
7. Открыть календарь опубликованных сроков или запросить объяснение AI.

Для проверки без выгрузки и секретов создайте проект без юрлица, выберите «разработка продукта». «Старт-1» будет показан с завершённым приёмом; инструменты для юридических лиц не станут подходящими проекту автоматически. Для ручного бизнес-профиля можно ввести свой действительный ИНН и подтвердить сведения самостоятельно. Не используйте вымышленные компании как реальные.

## Архитектура

```text
MAX / браузер → React/Vite miniapp → Express API
                                    ├─ CompanyDataService → FNSRegistrySnapshotProvider → SQLite
                                    │                        + МСП / численность / доходы-расходы
                                    ├─ OfficialSnapshotProvider → FundingCatalogService
                                    │                            → deterministic matching → strategy
                                    └─ privacy boundary → OAuth/token cache → GigaChat
MAX bot → быстрый диалог без пароля → тот же Express API
```

Код: `miniapp/api-server/company-data`, `miniapp/api-server/funding-catalog`, `miniapp/src/business`. `support-model.ts` сохранён для документов и совместимости; старые правила покрыты тестами. Legacy adapter берёт факты из официального каталога. Synthetic XML, компании и программы существуют только в `miniapp/api-server/tests/fixtures`.

`FundingNeed`: обязательна только цель. Сумма — внешняя потребность; собственные средства указываются отдельно. `ProjectProfile` содержит регион, отрасль, стадию, команду и потребность, не требует ИНН. `applicantTypes` проверяется как обязательное ограничение.

Matching проверяет известные ограничения, цель, диапазоны суммы/срока и статус приёма. Неизвестный факт не проходит проверку. Часть официальных условий требует дополнительной проверки оператором и остаётся `need_more_data`. Закрытые и будущие отборы не попадают в «Подходит сейчас». Неполное покрытие суммы — `partial`, документы учитываются отдельно. Score — техническое соответствие, не вероятность одобрения. Поручительство повышает приоритет при нехватке залога, но не считается выдачей денег. Лимиты вариантов в стратегии не суммируются.

## ФНС и локальный индекс

Для поиска без выгрузки полного реестра задайте `DADATA_API_KEY` на API-сервере. Используется документированный [findById/party](https://dadata.ru/api/find-party/) с поиском головной организации по точному ИНН. При наличии ключа выбирается DaData; без него сохраняется провайдер локального индекса ФНС. Ошибки доступа и лимита не заменяются ответом «компания не найдена».

Ключ хранится в GitHub Actions secret `DADATA_API_KEY`; deploy передаёт его по SSH в `/opt/app/.env.dadata` с правами `600`. Файл исключён из Git и загружается только API-сервером. Клиент вызывает наш `/api/company/:inn`. Ответы кэшируются в памяти на 15 минут, параллельные одинаковые запросы объединяются. `company-data/smoke-check.cjs` проверяет реальное автозаполнение после публикации.

Данные DaData помечаются `mode: aggregator` с источником каждого поля. Численность, налоги, финансовые показатели и МСП доступны в зависимости от ответа и тарифа; отсутствие поля остаётся неизвестным. Доходы не подменяют выручку, год финансовой отчётности не приписывается численности. Поиск по ИНН не подтверждает полномочия пользователя.

Никаких агрегаторов, scraping или private API. Поддержаны официальные XML:

- [ЕГРЮЛ/ЕГРИП для интеграции](https://www.nalog.gov.ru/rn77/service/egrip2/), выбранные поля форматов ЕГРЮЛ 4.07/4.08 и ЕГРИП 4.06/4.07. Форматы 4.08/4.07 — [приказ ФНС № ЕД-7-14/613@](https://www.nalog.gov.ru/rn77/about_fts/docs/16493030/). Доступ к полным выгрузкам требует официальных атрибутов доступа/абонентского обслуживания; приложение их не подменяет неофициальным API.
- [Реестр МСП — документация](https://rmsp.nalog.ru/developers.html), XML 4.06. Отсутствие записи в частичной выгрузке не доказывает отсутствие статуса МСП.
- [Среднесписочная численность](https://www.nalog.gov.ru/opendata/7707329152-sshr2019/), `СведССЧР/@КолРаб`.
- [Доходы и расходы](https://www.nalog.gov.ru/opendata/7707329152-revexp/), `СумДоход`, `СумРасход`.

**Доходы не приравниваются к выручке.** В текущем импортере `income` и `expenses` сохраняются отдельно; `revenue=null`. Для выручки нужен официальный набор, который прямо содержит этот показатель, и отдельный документированный адаптер. `ДатаСост` — дата состояния данных, не отчётный год; период передаётся через `--period` после проверки паспорта набора. Без подтверждённого периода поле периода остаётся `null`.

Каждый заполненный факт содержит provenance: источник, URL, дату, при наличии — период. Возраст вычисляется по регистрационной дате с пометкой `derived`. ФИО ИП, директоров, учредителей и полный адрес не сохраняются. Название ИП без ФИО может оставаться пустым. Фермерский бизнес определяется также по ОКВЭД; КФХ не считается единственной допустимой формой АПК.

Получите законный доступ к выгрузке ЕГРЮЛ/ЕГРИП либо скачайте разрешённый официальный файл. Затем:

```bash
npm run sync:fns -- --dataset registry --file /absolute/path/EGRUL.xml \
  --source-url https://www.nalog.gov.ru/rn77/service/egrip2/ \
  --updated-at YYYY-MM-DD

npm run sync:fns -- --dataset sme --file /absolute/path/SME.zip \
  --source-url https://rmsp.nalog.ru/developers.html \
  --updated-at YYYY-MM-DD

npm run sync:fns -- --dataset employees --file /absolute/path/employees.zip \
  --source-url https://www.nalog.gov.ru/opendata/7707329152-sshr2019/ \
  --updated-at YYYY-MM-DD --period 2025

npm run sync:fns -- --dataset financials --file /absolute/path/revexp.zip \
  --source-url https://www.nalog.gov.ru/opendata/7707329152-revexp/ \
  --updated-at YYYY-MM-DD --period 2025
```

`--file` можно заменить на `--url` с официальным HTTPS-адресом файла ФНС. Даты/период в примере замените значениями проверенного паспорта. Укажите `--dir` абсолютным путём: npm запускает CLI из `miniapp/api-server`; для пути относительно корня используйте `/absolute/path/MAX_HACKATHON/fns-data`. Значение по умолчанию без `--dir` — `fns-data` в корне репозитория.

По умолчанию импорт делает upsert и сохраняет более свежие записи. `--replace` очищает только выбранный dataset в одной транзакции — используйте лишь для полной выгрузки, не для одного фрагмента многотомного набора. Не запускайте импорты параллельно. Для полного составного снимка сначала импортируйте все его части в отдельный `--dir`, затем укажите этот каталог при перезапуске API.

XML/ZIP читаются потоком, UTF-8 и Windows-1251; DTD/XXE запрещены. Архив не извлекается в произвольные файловые пути. Ограничения: download 2 ГБ, один XML 4 ГБ, суммарное расширение ZIP 20 ГБ, 10 тыс. элементов. Для больших источников используйте локальные отдельные фрагменты. Ошибка откатывает импорт; сохраняются SHA-256, URL, даты и статистика. Это выборочный parser полей, а не полная XSD-валидация каждой выгрузки. Данные и SQLite не входят в git.

На чистом запуске индекс отсутствует. `GET /api/providers/status` должен показать `missing`; это корректное состояние, а не успешная интеграция.

## Локальный запуск

При открытии и обновлении страницы сначала появляется экран входа. Пароль: `20042004`.
Это локальный экран доступа для демонстрации, а не серверная авторизация: API остаётся без изменений.
После входа сохраняются прежние профиль, заявки и остальные данные рабочего пространства.
Оформление использует тему проекта `vkhackathon-main`; дополнительные сценарии оформлены в `miniapp/src/business/product.css`.

Node.js **22.13+**, npm. SQLite использует встроенный `node:sqlite` (в Node 22 возможен ExperimentalWarning).

```bash
npm ci --prefix miniapp
npm ci --prefix miniapp/api-server
npm ci --prefix chatbot
cp .env.example .env        # только если .env ещё нет
npm run api:dev             # отдельный терминал, порт 3002
npm run dev                 # отдельный терминал, порт 3000
npm test
npm run build
```

Vite проксирует только `/api/`; модули `/api-server/` не уходят в API proxy. Если порт занят, завершите свой старый процесс или используйте свободный порт (`PORT=3012 npm run api:dev`). Не подключайте другой backend к Vite без изменения proxy.

```bash
curl http://localhost:3002/api/health
curl http://localhost:3002/api/providers/status
curl http://localhost:3002/api/funding/status
curl http://localhost:3002/api/ai/status
curl -H 'Content-Type: application/json' -d '{"profile":{},"need":{"purpose":"покупка оборудования","amount":10000000,"preferredTermMonths":60}}' http://localhost:3002/api/funding/match
```

## ENV, GigaChat и MAX

| Переменная | Назначение |
|---|---|
| `PORT` | API, по умолчанию 3002 |
| `APP_ORIGIN` | CORS origins через запятую; локально `http://localhost:3000` |
| `FNS_DATA_DIR` | Каталог индекса SQLite; без значения — корневой `fns-data` |
| `GIGACHAT_AUTH_KEY` | Backend-only Authorization Key из кабинета GigaChat |
| `GIGACHAT_SCOPE` | По аккаунту; по умолчанию `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | По умолчанию `GigaChat-2-Pro`; модель должна быть доступна аккаунту |
| `NODE_EXTRA_CA_CERTS` | Необязательный путь к доверенному PEM, **до запуска Node** |
| `BOT_TOKEN` | Общий токен MAX для бота и проверки подписи на API |
| `BOT_API_URL` | Адрес API для чат-бота; по умолчанию `http://127.0.0.1:3002` |
| `MINIAPP_URL` | Публичный HTTPS URL вашего frontend |
| `MAX_BOT_USERNAME` | Имя зарегистрированного бота для `https://max.ru/<bot>?startapp` |

GigaChat: OAuth, кеш токена, объединение параллельных обновлений, один повтор после 401, таймауты и обработка ошибок. `GET /api/ai/status` отличает настройку от подтверждённого успешного запроса. До первой успешной генерации configured=true, checked=false, status=unavailable, reason=not_verified. Без ключа — not_configured. Новый `/api/ai/assist` использует контекст, историю, вызовы функций и поиск по эмбеддингам; известные реквизиты скрываются, свободный текст сохраняет смысл. Тексты документов передаются после отдельного запуска пользователем. Старый `/api/assistant` сохраняет полную токенизацию свободного текста и политику strict-v1 для совместимости. Модель не меняет рассчитанные статусы соответствия и не выполняет неподтверждённые изменения профиля.

В окружении текущей проверки ключи отсутствовали, а Node TLS без дополнительного CA вернул `SELF_SIGNED_CERT_IN_CHAIN` для OAuth и `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` для API GigaChat. Получите доверенную цепочку из [официальной инструкции GigaChat о сертификатах](https://developers.sber.ru/docs/ru/gigachat/certificates) и настройте PEM; не отключайте TLS. Например, `NODE_EXTRA_CA_CERTS=/absolute/path/trusted.pem npm run api:dev`. Запись пути только в dotenv недостаточна: Node читает эту переменную до исполнения JS.

MAX: `npm run build:chatbot && npm run start:chatbot`. Бот предоставляет подбор, компанию по ИНН, AI, сохранённые меры, сроки, черновики с TXT и управление подпиской без отдельного пароля. Компания и подписка общие с мини-приложением; черновики и история чата хранятся отдельно. [Сценарии, настройка и границы чат-бота](docs/chatbot.md). Используются `platform-api2.max.ru` и [документированные deep links](https://dev.max.ru/docs/webapps/introduction). Параметры открытия меры не аутентифицируют пользователя. Проверенные новые меры доставляются существующим планировщиком API; отображение push зависит от настроек MAX и телефона.

## Docker

```bash
mkdir -p fns-data
docker compose up --build
# optional bot, only after token + public HTTPS registration:
docker compose --profile bot up --build
```

Frontend: `http://localhost:3000`; API: `http://localhost:3002`. Nginx обслуживает Vite build и проксирует API. FNS volume read-only; импорт выполняйте отдельно на хосте и перезапускайте API при смене каталога. Для дополнительного CA добавьте override compose с read-only PEM mount и `NODE_EXTRA_CA_CERTS=/certs/trusted.pem` в API. Файл `.env`/сертификаты не копируются в образы. Docker не заменяет HTTPS ingress для MAX; TLS завершается вашим reverse proxy.

## Данные, безопасность и ограничения

- Профиль, проект, потребность, закладки и черновики: versioned localStorage v2 с миграцией. Прежние synthetic профили отбрасываются; сохранённые ID и заявки фильтруются по реальному каталогу. Облачной синхронизации нет.
- Локальная проверка текста ищет упоминания разделов. AI-проверка анализирует показанный текст и его согласованность с проектом. Обе не подтверждают юридическую силу и подлинность. Файл читается на устройстве, в AI передаётся текст после отдельного нажатия.
- Календарь содержит только опубликованные даты. Монитор официальных сайтов работает каждые шесть часов; события доступны в приложении. Новые материалы расширяют поисковую базу, формальный каталог требует проверки.
- `.env`, PEM/ключи и datasets игнорируются. Backend-only secrets, body limit 48 КБ (384 КБ для `/api/ai/assist`, включая максимум 60 000 символов документов), CORS allowlist, общий rate limit 15 AI/120 остальных запросов в минуту, до четырёх одновременных AI-запросов, no-store. За reverse proxy правильно настройте сетевой периметр; общий proxy IP может делить rate limit между клиентами.
- API read-only для каталога/профилей; локальные application statuses только draft/collecting_documents/ready_for_review. Нет платежей, банковских API, автоматической подачи и гарантии одобрения.
- Реальная ФНС требует наполненного индекса. SME/численность/финансы дополняют запись реестра, а не создают компанию по догадке. Годовая численность не равна текущему штату.

## API, DATA-API и deployment

`openapi.yaml` описывает runtime endpoints, JSON errors `{error, code}`, nullable поля и iCalendar. `DATA-API.yaml` содержит шесть повторяемых публичных проверок в формате [reference организаторов](https://gitverse.ru/stasnorman/example-data-api), проверен его валидатором. **Перед передачей укажите реальный HTTPS `api.baseUrl`: публичный адрес пока не предоставлен.** Company check намеренно отсутствует до наполнения реального индекса. Проверка `/api/ai/status` не расходует токены и не утверждает готовность AI.

Автодеплой на `main`: установка зависимостей, проверка production-сервера, сборка frontend, запуск `opora-frontend` через `ecosystem.config.cjs`, перезапуск API и существующего `opora-bot`. Frontend обслуживает только `miniapp/dist` с gzip и кешированием; `/api/` проксируется на `127.0.0.1:3002`. Vite dev server в публичном окружении не используется. Проверка после запуска требует production HTML, сжатый JS, кеширование и работающий API. На сервере нужны Node 22+, переменные окружения и официальный индекс. Изменённые ENV применяйте согласно конфигурации PM2 (`--update-env` при необходимости).

Для локальной проверки production: `npm run build --prefix miniapp`, затем `npm start --prefix miniapp` при работающем API на 3002. По умолчанию frontend слушает `127.0.0.1:3000`; порт можно задать через `PORT`. `npm run check:production --prefix miniapp` проверяет фактическую выдачу. HTTPS по-прежнему завершает внешний reverse proxy. На сервере сборка сохраняет старые файлы с хешами для уже открытых сессий; файлы без хеша кешируются только на час. Экран входа загружается отдельно, основной код начинает подгружаться при фокусе на пароле. При ошибке сети вход можно повторить.

Тесты включают старые правила/CompanyData/privacy и новые XML/SQLite/official snapshot/startup/API/storage/ICS сценарии. `docs/verification.md` содержит аудит controls и список ручной проверки; `docs/official-sources.md` — границы подтверждения источников.
