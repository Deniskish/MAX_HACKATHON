## Браузер

Автоматизация Playwright с установленным Yandex Chromium, headless, отдельный временный профиль. Пользовательский браузер и его localStorage не изменялись. Playwright установлен вне репозитория, не является зависимостью приложения.

Основной проход на **390×844**, desktop **1440×900**, дополнительные проверки ширины **360/430/768**. После исправлений горизонтального выхода элементов не обнаружено, ошибок JavaScript и React console errors в пройденном сценарии нет.

Проверено:

1. Создание проекта без ИНН, сохранение после reload, цель и deterministic matching.
2. Поиск «Старт-1», сохранение, подробности, disabled подготовка закрытого конкурса.
3. Ввод checksum-valid реального ИНН, честная ошибка отсутствующего ФНС provider, ручное заполнение АО/региона/ОКВЭД.
4. Поиск «Проекты развития», создание локальной заявки, описание, чек-лист, отметки документов.
5. При ненастроенном AI — явно обозначенный локальный шаблон, редактирование и скачивание TXT.
6. Подтверждение сверки комплекта, статус «Комплект готов к проверке перед подачей · не отправлено», сохранение после reload.
7. Открытие календаря, скачивание корректного ICS с опубликованным архивным событием.
8. Навигация desktop/mobile, отправка AI-вопроса по Enter, явное сообщение 503 и объяснение по правилам, переход из ответа к карточке программы.

Обнаруженные и исправленные дефекты: одинаковые React keys у чек-листа и редактора создавали повторные элементы; фильтры выходили за правую границу мобильного экрана; длинный стартовый CTA обрезался; поле редактора получало нестабильное accessible name. Повторный проход успешен.

## Что требует реальной настройки и ручной проверки

1. Получить официальную выгрузку ЕГРЮЛ/ЕГРИП; импортировать её CLI. Затем добавить МСП, численность и доходы/расходы с подтверждёнными датами и периодами. Сверить один реальный ИНН с оригиналом выгрузки, источник каждого поля, 404 отсутствующей записи. Fixtures не заменяют эту проверку.
2. Задать `GIGACHAT_AUTH_KEY`, разрешённый scope и модель. В существующем локальном `.env` модель явно задана как `GigaChat`; она не перезаписана. Новый default/example — `GigaChat-2-Pro`.
3. В этой среде TLS-пробы Node без auth дали `SELF_SIGNED_CERT_IN_CHAIN` (OAuth) и `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` (API). Настроить доверенный PEM до старта Node через `NODE_EXTRA_CA_CERTS`; TLS verification не отключать. Затем проверить успешный AI ответ и переход статуса в ready.
4. Указать настоящий HTTPS origin в `MINIAPP_URL`, `APP_ORIGIN`, `DATA-API.yaml`; текущий адрес в DATA-API — явный незаполненный параметр, не deployment.
5. Задать `BOT_TOKEN`, при необходимости `MAX_BOT_USERNAME`; в MAX на iOS/Android проверить `/start`, `/help`, открытие mini-app, deep link на существующую программу, safe areas/клавиатуру, официальный URL, копирование документа и загрузку ICS. Персональные push не реализованы.
6. На машине с Docker выполнить `docker compose build` и `docker compose up`, проверить health/provider statuses, nginx proxy и права доступа к volume ФНС. Для GigaChat при необходимости смонтировать PEM и передать переменную контейнеру согласно README.
7. После разрешённого deployment проверить публичный frontend/API и выполнить DATA-API checks на настоящем URL. Автодеплой из `denis-dev` не запускался.
