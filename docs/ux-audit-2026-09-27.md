# Аудит интерфейса и дублирования «Опоры»

Дата: 27.09.2026. Проверенная версия: `cf2d12a`.

## Реализация доработок — локально поверх f605d26

Этот раздел описывает внесённые изменения. Ниже сохранён исторический аудит исходных версий. Коммит, push и деплой в рамках этой доработки не выполнялись.

### Два подтверждённых дефекта

- **Единая готовность.** `application-readiness.ts` используется итоговым статусом, индикаторами и этапами подготовки. Неопубликованный список документов не считается завершённым. Для финансовых инструментов в подготовке нужен положительный целочисленный бюджет; у гарантии, налоговой, имущественной и консультационной поддержки пустой бюджет необязателен. Это правило подготовки комплекта в приложении, а не утверждение об обязательных полях формы каждого оператора. Любое изменение проекта, бюджета, текста или отметок документов снимает ручное подтверждение проверки.
- **Браузерный тест исправлен и расширен.** Устаревший переход к ЕСИА из настроек удалён. Проверяются фактические действия: подготовка → проверка → официальный сайт. Скрипт запускается через `npm run test:ux --prefix miniapp`; добавлен workflow `ux-check.yml`, который также выполняется перед деплоем. Реальный запуск нового workflow в GitHub ещё не происходил: изменения локальные.

## Вывод

Основная проблема — несколько параллельных способов выполнить одну задачу: подобрать поддержку, проанализировать бизнес, проверить документы. Интерфейс выглядит цельно, но логика переходов и результатов местами различается. Приоритет — объединить сценарии и состояния, затем упростить тексты и компоненты. Полная смена дизайна не нужна.

Аудит: чтение клиентского кода и связанных серверных модулей; просмотр восьми состояний экранов в Chromium (393×810, тёмная тема; 320×810, светлая тема). Для браузера использованы контрольный профиль, официальный встроенный каталог и управляемый отказ AI. Живые ответы AI, реальная отправка заявок и поведение клавиатуры внутри MAX на физическом телефоне здесь не проверялись. Горизонтального переполнения и JavaScript-ошибок на просмотренных экранах нет. Изменений в приложение не внесено.

P0 — достоверность ключевого результата; P1 — основной сценарий и понятность; P2 — упрощение и сопровождение. Оценки интерфейса — экспертные гипотезы, кроме явно воспроизведённых проблем; их стоит подтвердить коротким пользовательским тестированием.

## P0: согласовать результаты и реальные возможности

### 1. Единая логика подбора

**Сейчас:** «Для вас» пропускает импортированные меры только после AI-приоритизации или уведомления. Отдельная форма «Найти варианты» вызывает проверку правил по всему каталогу. Эти результаты имеют разные основания и могут не совпадать. Счётчик «Подходит по правилам» при этом учитывает ещё и готовность документов, поскольку считает только `eligible`.

**Доработка:** один результат подбора с раздельными состояниями «совпадают известные условия», «нужно уточнить», «AI объяснил рекомендацию». Готовность заявки считать отдельно от соответствия бизнеса. При недоступном AI сохранять проверяемые варианты по правилам, не называть их результатом AI. Не выдавать отсутствие анализа за отсутствие поддержки.

**Готово, когда:** при одинаковых профиле и цели каталог, результаты подбора и счётчик согласованы; отказ AI не создаёт ложный ноль.
