# Быстрые сценарии в MAX

Бот работает через существующий API «Опоры». Пароль мини-приложения не участвует во входе в чат. Пользователь определяется по событию MAX, полученному библиотекой бота; обработка личных данных разрешена только в личном диалоге.

## Путь пользователя

- `/start`: короткое меню; можно сразу задать вопрос AI или прислать ИНН.
- «Нужно 5 млн на оборудование»: цель и сумма распознаются без анкеты. При сохранённом бизнесе сразу показываются варианты, иначе бот просит ИНН или регион и направление проекта.
- «Найти поддержку»: ИНН → подтверждение найденной компании → цель → сумма или пропуск → три меры за раз. Компания из аккаунта повторно не запрашивается.
- Карточка меры: размер помощи, срок, статус известных условий, официальный источник, AI-разбор, список документов и сохранение.
- Подготовка: описание проекта → AI-черновик → просмотр или TXT → официальный сайт оператора. Бот не выдаёт черновик за принятую заявку и не подтверждает полномочия владельца компании.
- Проверка документов: текст до 6 000 символов. Загрузка PDF, изображений и OCR остаются в мини-приложении; в чате для них предлагается ссылка.
- «Мой бизнес»: данные, AI-анализ, замена или удаление с подтверждением.
- «Сообщения MAX»: явное включение/отключение существующей подписки; остановка бота отключает рассылку.
- `/cancel` или «Меню»: выход из текущего шага. `/saved` — меры, `/applications` — черновики, `/calendar` — опубликованные сроки сохранённых мер и черновиков.

Нет отдельного каталога или модели соответствия для чата: используются `/api/company/:inn`, `/api/funding/match`, `/api/funding/catalog`, `/api/ai/assist`, `/api/account`, `/api/notifications`.

## Данные и границы синхронизации

Компания хранится в общем серверном аккаунте MAX и доступна мини-приложению. Подписка на меры также общая. Задача, сохранённые меры, последние сообщения и до трёх черновиков бота сохраняются отдельно в `bot_workspaces` в существующей SQLite-базе `notifications.sqlite`. Локальные черновики и файлы мини-приложения автоматически не переносятся в чат.

Первый шаг подготовки сообщает о сохранении черновика в аккаунте. Удаление компании через API очищает серверное состояние чата; изменение ИНН сбрасывает контекст старой компании при следующем обращении. Отдельный черновик можно удалить. Исходный текст документа для AI-проверки не сохраняется в истории успешной проверки; неудачное действие временно сохраняется для повтора. Обычный вопрос и ответ хранятся в сокращённой истории последних шести сообщений.

`GET /api/bot/workspace` возвращает `{ data, revision }`; `PUT` сохраняет состояние только при совпадении ревизии. Ограничения: 80 000 символов JSON, 30 сохранённых мер, 3 черновика, 25 последних идентификаторов событий. Повтор одного события не запускает сценарий заново. В одном процессе события пользователя идут последовательно; конфликт ревизий между процессами требует обновления данных, не затирает их.

## Подключение

Используются `BOT_TOKEN`, `MINIAPP_URL` и необязательный `BOT_API_URL` (по умолчанию `http://127.0.0.1:3002`). При отдельном размещении бота укажите HTTPS-адрес API. Токен MAX должен совпадать у API и бота; в запросах он не передаётся.

Бот подписывает метод, путь, ID пользователя из MAX, время, nonce и JSON тела HMAC-SHA256 с отдельным производным ключом `opora-bot-api-v1`. API проверяет подпись, срок и повтор nonce до назначения пользователя и расчёта лимитов. Подписанный запрос не является имитацией WebApp initData; один заголовок с ID не даёт доступа к аккаунту. Лимит AI учитывается отдельно для каждого пользователя бота.

Запуск: `npm run build --prefix chatbot`, затем `npm start --prefix chatbot`. Не запускайте второй процесс long polling с тем же токеном рядом с рабочим ботом. Транспорт наследует текущий long polling проекта; переход на webhook и его публичный маршрут — отдельная инфраструктурная работа.

Проверки: `npm test --prefix chatbot` и `npm test --prefix miniapp/api-server`. Они не отправляют сообщения в MAX и не расходуют запросы живого AI. Перед показом на телефоне пройдите: старт без пароля → ИНН → подбор → сохранение → AI → черновик → TXT → источник, затем повторный вход и отключение подписки.

SDK и кнопки сверены с [официальной документацией MAX](https://dev.max.ru/docs/chatbots/bots-coding/js) и [описанием клавиатур](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard).
