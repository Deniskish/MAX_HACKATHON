# Автоматический каталог и уведомления о поддержке

Дополнено независимыми официальными источниками. Актуальная архитектура, ограничения, проверка и мониторинг описаны в [multi-source-funding.md](multi-source-funding.md). Ниже — исходная интеграция Минфина и общие настройки.

## Что подключено

Официальный портал Минфина «Электронный бюджет»: https://promote.budget.gov.ru/public/minfin/activity. Сервер загружает опубликованные отборы на субсидии, сохраняет ссылку на объявление, организатора, даты и известные категории получателей. Существующие шесть программ остаются в каталоге.

Проверка выполняется раз в 15 минут. Это периодическое обновление, не поток событий и не гарантия мгновенной доставки. Первые 1 000 карточек обновляются каждый цикл; если активные отборы продолжаются, обход расширяется до 5 000. Отдельный сохранённый курсор постепенно обходит остальные страницы. Портал содержит и архив: его общее число записей нельзя выдавать за число действующих мер.

На локальной проверке 26 сентября 2026 года источник вернул 43 370 записей, из которых первый проход импортировал 990 незакрытых отборов. Каталог вместе с прежними программами содержит 996 записей. Числа меняются со временем. Это один большой официальный источник, не все меры поддержки России.

Нет публичного SLA или договора API: структура портала может измениться. При ошибке сохраняется последняя успешная копия; статус доступен через `/api/funding/live-status`. Неизвестные условия не становятся подтверждёнными. Общий бюджет субсидии не подставляется как сумма одному получателю.

## Как отбираются уведомления

1. Пользователь добавляет бизнес и включает уведомления в «Мой бизнес». Отдельный переключатель разрешает сообщения бота MAX.
2. Сервер проверяет подписанную MAX `initData`. ID из произвольного тела запроса не принимается.
3. Предварительный фильтр учитывает статус приёма, известные ограничения, сумму и совпадения направления с названием отбора. После получения подробных условий проверяется территория.
4. GigaChat получает параметры бизнеса и полный доступный текст условий. Рекомендация требует обоснования с цитатами, буквально найденными в источнике. Неполные сведения, отсутствие AI и недоступный источник не создают вымышленных рекомендаций.
5. Подходящая возможность появляется в уведомлениях приложения. При разрешении пользователя сервер отправляет сообщение MAX со ссылкой на карточку, даже при закрытом приложении. Финальное соответствие требованиям и одобрение остаются у оператора программы.

Первое подключение проверяет также уже существующие активные меры. Затем проверяются новые версии записей. Предварительный поиск по названию консервативен и может пропускать релевантные программы: полнота охвата не гарантируется. Изменение только подробного текста без изменения карточки пока не создаёт новую версию уведомления.

Очередь обрабатывается каждую минуту: не более 12 проверок за проход и двух на пользователя; одна отправка пользователю за проход. При большом количестве подписок доставка занимает больше 15 минут. Реестр отправленных мер в SQLite защищает от повторных уведомлений после изменения версии. Подтверждённые временные HTTP-ошибки отправки повторяются с растущей задержкой, максимум восемь попыток. При неоднозначном результате запроса или аварии после начала отправки автоматического повтора нет: состояние `unconfirmed` или `sending` разбирает команда. Ошибки доступны только в мониторинге. Абсолютная гарантия доставки «ровно один раз» без поддержки идемпотентности со стороны MAX отсутствует.

Смена параметров скрывает прежние рекомендации и отменяет ожидающие отправки старого профиля. Отключение всех уведомлений удаляет подписку и её историю. Блокировка бота не мешает просматривать уведомления приложения.

После добавления компании или проекта в приложении появляется поздравление, которое сохраняется на устройстве. Редактирование той же компании не создаёт повтор. В «Мой бизнес» есть удаление с подтверждением: очищаются профиль, параметры подбора, AI-контекст и поздравление. При открытии через MAX сначала удаляется серверная подписка; при сетевой ошибке профиль остаётся и можно повторить попытку. Черновики и избранное сохраняются, но старые черновики не становятся данными новой компании.

## Настройка сервера

Используется Node.js 22 с доступным `node:sqlite` (как существующий индекс компаний). Переменные:

| Переменная | Назначение |
| --- | --- |
| `FUNDING_SYNC` | `off` отключает обновление каталога и фоновые уведомления; по умолчанию включены |
| `OPORA_FUNDING_DIR` | Постоянный каталог для `catalog.json`, `notifications.sqlite` и WAL; по умолчанию `miniapp/api-server/source-data/funding` |
| `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` | Серверный доступ к GigaChat |
| `BOT_TOKEN` | Токен того же бота, через который открывается мини-приложение; проверка авторизации и отправка сообщений |
| `MAX_BOT_USERNAME` | Имя бота для ссылки `https://max.ru/<bot>?startapp=<id>`; предпочтительно задать |
| `MINIAPP_URL` | HTTPS-адрес приложения для резервной ссылки; по умолчанию `https://business-opora.ru` |

`restart-api.cjs` сохраняет эти настройки PM2 и при необходимости берёт параметры бота из процесса `opora-bot`, не печатая секреты. Каталог данных не должен удаляться при деплое; резервное копирование SQLite нужно выполнять согласованно с WAL. Текущий деплой через Git не удаляет этот игнорируемый каталог.

Хранятся MAX ID и разрешённые параметры подбора. ИНН, название компании и файлы в подписку не включаются. Авторизация MAX действует до 24 часов; затем нужно повторно открыть приложение. Бот может отправлять сообщения только пользователю, который начал с ним диалог и не заблокировал его.

Для портала Минфина добавлен публичный промежуточный сертификат GlobalSign, отсутствующий в выдаваемой сервером цепочке. Доверие ограничено соединением с этим источником; проверка TLS не отключается.

## Проверка реализации

- API: 123 теста проходят, включая подпись MAX, изоляцию пользователей, смену бизнеса, отключение, цитаты AI, дубликаты, повторную доставку, сохранение SQLite и блокировку параллельных обработчиков.
- Интерфейс: 55 тестов проходят. Сборки API и приложения проходят. Ещё четыре теста проверяют production-сервер и сохранение настроек при перезапуске через PM2.
- Реальный источник: загрузка каталога и подробных условий проверена локально.
- Браузер: 320 px / светлая тема и 393 px / тёмная тема; просмотр 30/60 карточек, включение и отключение обоих каналов, отсутствие горизонтального переполнения.
- Переходы: прямая ссылка и MAX `startapp` открывают нужную карточку после загрузки каталога; закрытая карточка не открывается повторно при обновлении. Переход из уведомления сохраняет отметку прочтения на сервере.
- Внешние ответы GigaChat и доставка MAX в автоматических тестах подменены контролируемыми ответами. Настоящие сообщения пользователям при проверке не отправлялись. Сквозная доставка с рабочими ключами на сервере пока не подтверждена.

Деплой дополнительно запускает `funding-catalog/smoke-check.cjs`: проверяет настоящий источник, ответ GigaChat на условия реального отбора и авторизацию бота MAX через `/me`. Проверка не рассылает сообщения пользователям. Статус конкретного развёртывания смотрите в GitHub Actions.
