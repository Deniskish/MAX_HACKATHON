# Мобильный интерфейс

Отдельный файл для дальнейшей доработки: [MAX Хакатон — мобильные страницы](https://www.figma.com/design/8Ab4TqvQ7fCoKtpGNtIPAM).

## Компоновка

- На ширинах до 767 px шапка, прокручиваемый контент и нижняя навигация занимают разные строки. Навигация не накладывается на карточки и поля.
- В MAX высота берётся из [`WebApp.getViewportSize()`](https://dev.max.ru/docs/webapps/bridge), в браузере и при недоступности метода — из `visualViewport`. Размер обновляется после загрузки Bridge, изменения окна и возврата на страницу. Во время ввода экранная клавиатура уменьшает доступную высоту; масштабирование жестом не меняет компоновку.
- У диалогов отдельная строка управления и прокручиваемое содержимое. Формы проекта и экспорт используют native dialog с удержанием фокуса и закрытием по Escape.
- Заголовок карточки и закладка располагаются рядом в flex-контейнере; длинный текст переносится, не попадая под кнопку.
- Формы, кнопки, документы и профиль выровнены в одну колонку. Основные элементы управления имеют высоту не менее 44–48 px.
- Главная обновлена по предоставленному референсу с исходными PNG: [композиция, изображения и действия](home-reference.md). Шапка содержит небольшой логотип и колокольчик, нижняя навигация — четыре пункта в общей панели.
- Линия над «опора.» убрана. Активная вкладка снова выделена серой подложкой и оранжевыми значком и текстом; у неактивных вкладок нет залипающей светлой подсветки после касания.
- В Android-клиенте MAX убраны повторные системные отступы: его нативные панели уже ограничивают окно мини-приложения. Шапка имеет высоту 98 px, под навигацией остаётся 10 px. Платформа определяется через MAX Bridge; браузер и iOS сохраняют CSS safe-area. Те же правила применяются к диалогам и уведомлениям.
- Главная сохраняет тёмную палитру референса. На остальных страницах выбор светлой/тёмной палитры следует системной теме.

`mobile.css` отвечает за мобильную компоновку, `dark.css` — за тёмную палитру. Условия программ, данные ФНС, API, локальное хранение, расчёты и генерация документов остаются в существующих модулях.

## Страницы для дизайна

Макеты шириной 390 px включают вход и ошибку пароля, первый запуск, обе формы компании, проект без юридического лица, главную с потребностью, результаты подбора, каталог, сохранённое, события, календарь, профиль, заявки, помощника, все шесть карточек программ, подготовку документов, редактор и экспорт текста. Дополнительно представлены тёмные экраны.

Полные страницы экспортируются с раскрытыми пояснениями и всеми полями, независимо от высоты экрана. Это редактируемые слои импорта; общая библиотека компонентов в Figma не создавалась из-за лимита MCP Starter. Примеры компании и заявок заполнялись только в изолированном браузере для макета. Они не являются сведениями ФНС и не меняют рабочие данные пользователя.

## Проверка

Проверены 30 экранов на ширинах 320, 360, 390, 430, 600 и 767 px: 180 проверок границ, горизонтального переполнения и пересечения соседних элементов. Дополнительно проверен viewport высотой 420 px, вход, сохранение профиля после повторного входа, навигация, закладки, диалоги и подбор через настоящий локальный API. Отдельно проверены Manrope, ширина и отсутствие скрытого прокручиваемого содержимого в HTML-макетах для Figma.

После правки навигации дополнительно проверены 36 сочетаний трёх вкладок, шести мобильных ширин и двух тем. В браузере смоделированы различающиеся размеры WebView и MAX, поздняя загрузка Bridge, открытие/закрытие клавиатуры, масштаб native-размеров, ошибочные ответы и pinch zoom. Проверка на физическом устройстве с MAX отдельно не проводилась.

По скриншоту Android воспроизведены лишние отступы через Chromium `Emulation.setSafeAreaInsetsOverride`: 50 px сверху и 24 px снизу. Проверено их устранение после загрузки MAX Bridge, положение панели диалога и сохранение защитных отступов для браузера и iOS.

Команды проверки проекта:

```sh
npm run build:miniapp
npm --prefix miniapp test
```
