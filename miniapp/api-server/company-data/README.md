# Данные компании по ИНН

На этом этапе работает только `DemoCompanyDataProvider`. Сетевых запросов к ФНС,
коммерческим сайтам, private API и scraping в модуле нет. `.env.example` не меняется:
новые секреты, URL и переключатели режима сейчас не нужны.

## Архитектура

`GET /api/company/:inn` → `CompanyDataService` → `CompanyDataProvider`.

- `types.ts`: нормализованный `CompanyData`, контракт провайдера и происхождение каждого поля.
- `inn.ts`: общая для frontend/backend проверка длины и контрольных цифр. 10 цифр задают
  тип поиска ЮЛ, 12 — ИП/физлицо. Валидный ИНН не доказывает существование бизнеса,
  наличие статуса ИП или форму ООО/КФХ. Организационную форму нельзя выводить из длины.
- `demo-provider.ts`: четыре явно учебных снимка, без внешних запросов.
- `service.ts`: валидация до вызова провайдера, проверка соответствия ИНН и provenance,
  вычисление полных месяцев из известной даты регистрации, преобразование в существующий
  `Profile`. Matching продолжает использовать `Profile` из `support-model.ts`.
- `router.ts`: подключение провайдера через конструктор сервиса, HTTP-статусы и безопасные ошибки.
- `official-providers.ts`: **не реализованные** `FNSOpenDataProvider` и `SMERegistryProvider`.
  Вызов завершается `ProviderNotConfiguredError` (HTTP 503), а не успешным demo-ответом.

`CompanyDataResult = CompanyRecord | null`: null означает, что запись не найдена в
подключённом наборе. Сбой чтения/импорта должен бросать ошибку, а не возвращать null.
Провайдер возвращает `company`, `sources` и `provenance` для каждого известного поля.
Это позволяет впоследствии объединять регистрационные сведения и реестр МСП с разными
источниками/датами для отдельных значений, сохраняя этот же контракт.

`CompanyData` содержит ИНН, ОГРН/ОГРНИП (`ogrn`, строка), название, форму, регион,
дату регистрации (YYYY-MM-DD), возраст в полных месяцах, основной/дополнительные ОКВЭД,
численность, выручку в рублях, режим налогообложения, статус/категорию МСП,
источник, URL источника и дату снимка. Неизвестные поля — `null`, включая `isSme`:
отсутствие сведений не равно `false`. `okvedAdditional=null` означает неизвестность;
`[]` допустим только при явно известном отсутствии дополнительных кодов.
`sourceUrl=null` у demo, поскольку официального URL для этих данных нет.

HTTP 200 содержит обязательные `mode`, `company`, `sources` и дополнительные
`entityType`, `profile`, `provenance`. В `profile` известные поля переименованы
(`okvedMain` → `okved`, `taxRegime` → `tax`), `isSme` отображается в `yes/no/unknown`.
Пустые строки/числовые null соответствуют существующему `emptyProfile`; цели не угадываются.
`Profile.provenance` сохраняется вместе с профилем в прежнем localStorage-ключе;
старые сохранённые профили без metadata остаются совместимыми.

Происхождение поля содержит `sourceId`, `source`, `sourceUrl`, `updatedAt`, `mode`, `kind`.
У вычисленного возраста есть `derivedFrom: [registrationDate]` и `computedAt`;
`updatedAt` остаётся датой исходного снимка. Наличие provenance не удостоверяет
подлинность пользовательского запроса и не заменяет проверку актуальности источника.
Числовые поля будущего импортёра требуют явно определённых единиц и отчётного периода;
нельзя подменять выручку доходом или численность произвольным похожим показателем.

Статусы: 400 — неверный ИНН, 404 — нет записи в источнике, 200 — профиль найден;
503 — официальный провайдер не реализован; 502 — ошибка источника/его контракта.
Ответ не кэшируется (`Cache-Control: no-store`). Текущий endpoint ничего не пишет
в backend-хранилище и не вызывает GigaChat. ИНН в GET-пути может присутствовать в
журналах инфраструктуры: при реальном подключении настройте маскирование этого маршрута.

## Учебные профили

| ИНН | Пример |
| --- | --- |
| `9900000017` | ООО «Учебная мастерская» |
| `990000000041` | ИП «Учебный предприниматель» |
| `9900000024` | КФХ «Учебное поле» |
| `9900000031` | ООО «Учебная технология» |

Все ИНН — синтетические ключи с корректными контрольными цифрами. Они не проверены
по реестру; любое совпадение с реальным ИНН не делает fixture сведениями об этом лице.
Все названия, регионы, ОКВЭД, даты, цифры и статусы в наборе вымышлены.
У ИП специально отсутствуют дата регистрации, выручка, налоги и статус МСП;
численность 0 задана явно. ОГРН отсутствует у всех четырёх примеров.
Для других корректных ИНН возвращается 404, после которого доступен ручной ввод.

Frontend заполняет только известные поля, показывает источник и позволяет редактировать
все значения. Ручное изменение помечается `manual`; смена ИНН очищает старые факты,
сохраняя цели. При обновлении источника исчезнувшие автоматические факты очищаются,
а неизвестные источнику ручные значения сохраняются. Повторная загрузка известного
источнику поля заменяет его значение. Запрос отменяется при закрытии формы, повторном
открытии/запросе или смене ИНН; устаревший ответ не применяется.

## Подключение официальных данных — следующая стадия

- [Интеграция ЕГРЮЛ/ЕГРИП](https://www.nalog.gov.ru/rn77/service/egrip2/):
  документированные форматы выгрузок и порядок получения доступа.
- [Порядок доступа](https://www.nalog.gov.ru/rn77/service/egrip2/access_order/):
  условия и атрибуты доступа. Нельзя предполагать наличие бесплатного публичного REST API.
- [Реестр МСП — разработчикам](https://rmsp.nalog.ru/developers.html):
  форматы сведений для информационных систем и переход к открытым данным ФНС.

возможно только после реального импорта/адаптера и тестов. Сейчас никакая интеграция не заявляется.

реквизиты токенизируются, сырые `company`, `sources` и `provenance` не передаются.
Интеграционный тест проверяет именно тело запроса внешнему LLM-провайдеру.

## Локальная проверка

Из корня репозитория:

```sh
npm test
npm run build
npm run api:dev
# В другом терминале:
npm run dev
```

Откройте `http://localhost:3000`, «Начать с ИНН», введите один из четырёх примеров,
нажмите «Получить данные компании». Проверьте подписи источника, пустые поля ИП,
ручное изменение и сохранение после выбора цели.

```sh
curl -i http://localhost:3002/api/company/9900000017
curl -i http://localhost:3002/api/company/990000000041
curl -i http://localhost:3002/api/company/9900000018 # 400
curl -i http://localhost:3002/api/company/7707083893 # 404 в demo-наборе
```

Прокси Vite `/api/`, команды запуска и deployment не менялись. Не коммитьте реальные
снимки/секреты доступа; переменные окружения следует добавлять при реализации выбранного
официального канала, когда будут известны его реальные требования.
